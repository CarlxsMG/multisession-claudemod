# The UI in other languages

crew's UI speaks English by default and Spanish when asked. This page says where its text lives,
how to add a string, and how to add a language.

## What is translated, and what is not

- **Translated:** every word a person reads. The pane and its editor, the `/crew` command's help
  and replies (and its line in the command list), the status line, the toasts, the rows placed in
  the conversation, the bubbles' borders, the part and colour names of the editor, the
  personalities' names and their fixed lines, and a new mascot's catchphrase.
- **Never translated:** every text a model reads. The orchestrator's brief, the workers'
  preamble, the tool specs and results, the `[crew]` note, the header of a user's message to a
  worker, and the prompt that asks Haiku for mood lines are English whatever the UI speaks, and
  `tests/golden/model-text.ts` pins them. The Haiku prompt names the language it wants the lines
  in (`LANGUAGE_NAME`), so a mascot's lines match its UI.
- **Kept in English on purpose:** the four-letter words under a worker's card (`init`, `work`,
  `wait`, `done`, `fail`, `stop`, `CARD_LABEL` in `src/ui/labels.ts`), because four columns hold
  no translation of them, and the stored keys and share codes, which are data, not text.

## Where the text lives

| File | What it holds |
| --- | --- |
| `src/i18n/en.ts` | The English table, `en`. Its type, `Messages = typeof en`, is the shape every locale must have. Each key's comment says where it shows. |
| `src/i18n/es.ts` | The Spanish table, `es: Messages`. |
| `src/i18n/en-vibes.ts`, `es-vibes.ts` | Each personality's name and its fixed lines by mood, by the key a look stores. A delegating line names the worker as `{w}`. |
| `src/i18n/index.ts` | `t()`: the table of the locale the UI speaks now. |
| `src/i18n/locale.ts` | The locale: `Locale`, `chooseLocale`, `settleLocale`, `localeOfLanguage`, `LANGUAGE_NAME`. |

Read the text through `t()` at the moment it shows, never into a module constant: modules load
before the session settles its locale.

```ts
import { t } from '../i18n'

const label = t().pane.customize
const line = t().progress.calls(run.tools)
```

A string with a number or a name is a function in the table, so each language builds it its own
way, plurals included (`calls: n => \`${n} ${n === 1 ? 'call' : 'calls'}\``).

## How the locale is chosen

1. `hooks/register.tsx` passes the plugin's `language` option (`auto`, `en` or `es`, declared
   under `userConfig` in `.claude-plugin/plugin.json`) to `chooseLocale` when the plugin loads.
2. At session start, `settleLocale` takes that option; with `auto` it reads Claude Code's own
   `language` setting (`$.settings.read({ key: 'language' })`) and maps it with
   `localeOfLanguage`, which accepts names and codes in any case, with or without accents
   (`Español`, `spanish`, `es`, `es-ES`, `es_ES`, `castellano`). Anything else is English.
3. The mood lines Haiku wrote are kept with a signature that includes the locale, so a session in
   another language asks for a new batch once.

## Adding or changing a string

1. Add the key to `en.ts`, with a comment saying where it shows when that is not obvious.
2. Add the same key to `es.ts`. tsc fails while a locale misses a key or has one too many.
3. Use it through `t()`.
4. Check that it fits. The pane is 48 columns wide by default and works down to 34, and the
   width tests in `tests/progress.test.tsx` run in both languages; a longer word may need a
   shorter one.

Most tests read the Spanish UI (see CONTRIBUTING.md, Tests). A test of new text in English goes in
`tests/locale.test.tsx`.

If you do not speak Spanish, write the English and say so in the pull request: someone will add
the Spanish before it merges.

## Adding a language

Take Spanish as the model. For a language with code `xx`:

1. Copy `src/i18n/es.ts` to `xx.ts` and translate it, keeping every key.
2. Copy `src/i18n/es-vibes.ts` to `xx-vibes.ts` and write each personality's lines in that
   language, in character: five lines a mood, every delegating line with `{w}`. These are
   written anew more than translated.
3. Add `'xx'` to `Locale` in `src/i18n/locale.ts`, its English name to `LANGUAGE_NAME`, and the
   names and codes that mean it to `localeOfLanguage`.
4. Add the table to `TABLES` in `src/i18n/index.ts`.
5. Add `"xx"` to the `language` option's `options` in `.claude-plugin/plugin.json`.
6. Add the table to the loops of `tests/unit/i18n.test.ts`, which check that every catalog part,
   colour and personality has its words, and the language's names to its `localeOfLanguage` test.
7. If the `/crew` verbs should have words in that language, add them as aliases in
   `src/hooks/commands.ts`; the verbs of every language always work.
8. Add a `README.xx.md` if you will keep it in step with the English one.
